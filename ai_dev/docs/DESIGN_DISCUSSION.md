## 已确定约束

| 事项 | 约束 |
|---|---|
| 主工程 | 当前仓库的 ai_dev 目录 |
| 技术栈 | Vue + Bun；数据库使用 MySQL；需求后台、Pi 服务和工程脚本全部使用 Bun |
| 核心范围 | 最小实现 01 需求会话与流程编排、03 AI 代码开发；其他模块不实现，不建设空页面或模拟服务 |
| 网关边界 | 本地管理需求和会话、转发执行请求、汇总状态与结果；自身不直接调用 LLM |

| 引擎基础 | 搬迁 pi-web-demo 的 Vue 前端和 Pi Agent 版本后端，排除 DeepSeek Harness 专用服务 |

| 机器接入 | 固定本地 Mac，不实现机器注册、调度、远程连接或常驻远程节点协议 |
| 代码来源 | 创建需求时填写本机已有 Git 仓库，为需求准备独立持久目录和需求分支 |
| 首期预览 | 保留 Pi Demo 的 Web 页面预览、文件查看和代码差异；暂不接入真机、模拟器画面或完整桌面预览 |
| 工作区 | 一个需求对应一个持久工作区与需求分支 |

| 提交 | AI 自主决定提交时机和范围；成果对应固定代码 |
| 用户权限 | 本期不建设用户权限管理模块 |
| 设计优先级 | 本次技术栈约束、当前模块综述与所附网关图优先；不照搬旧技术评审稿的数据库选型 |

## 需要消除的表述歧义

- 图中的“主执行 Agent”指开发机侧自主执行者，不意味着同一需求只能有一个会话执行 Agent。
- 网关的流程编排负责任务与状态协调；Agent 的任务编排负责思考、计划与工具决策。
- 网关在本期是本地需求会话入口，不承载 02 的机器调度能力。
- SDK Runner 是目标应用中的执行能力；不纳入本期工程。

## 本轮已确认的范围收缩

用户明确首期最小化：只支持本地 Mac，直接复用 Pi Demo 前后端，不实现其他模块，也不支持资料。因此取消前轮 Linux、开发机登记、远程节点和文件解析建议。

搬迁中需要适配的核心差异仍然存在：原 Demo 按会话创建工作区，本需求按需求共享工作区；原 Demo 用本地 JSON 保存会话，新工程指定 MySQL。搬迁应保留原有交互和真实 Pi 工具循环，再处理这两项必要变化。

## 最终确认的工程方案

初始代码来源、首期预览范围及以下方案已由用户确认按推荐执行。

1. 同一工程内设置协作网关、Pi 执行服务两个 Bun 入口，沿用 Express，首期都在本地 Mac。网关管理业务与 MySQL，执行服务完成模型与本机工具循环；取代此前单进程建议。
2. 正常对话仅下发新消息及必要的需求变化；初始化或实例丢失时才提供初始化上下文或恢复检查点。不将传输增量等同于模型 Token 节省。
3. MySQL 保存需求、会话、执行记录和 Pi 上下文检查点，文件及 Git 工作区留在本地；初期采用三张业务表。只有网关访问数据库。
4. 不迁移整目录“撤销上一轮”和“清空历史”，保留停止、继续、新会话及差异查看；避免共享工作区被整目录恢复。

后续云端协作可复用服务边界，但首期不建设远程机器调度、网络隧道或云端部署。决策依据见 [双服务与会话增量 ADR](adr/0002-gateway-executor-session-sync.md)。

## 当前代码事实

- 用户已确认所有工程进程均使用 Bun，取消此前保留 Node.js Pi 服务的建议。迁移时须验证 Pi SDK、文件与 Shell 工具、流式事件和停止功能在 Bun 下的行为。
- MVP HTML 的会话回复、构建、测试和手机/桌面预览均为模拟，不能直接作为已接通的外部能力。
- pi-web-demo 有 Pi 与 DeepSeek Harness 两套真实引擎适配。既有已接受 ADR 选择 Pi，本工程先沿用该决定；多引擎能力留在适配边界，不把双引擎默认列入首期范围。
- 现有 Demo 按 appID + session 隔离工作区，与本工程按需求共享工作区不同；会话上下文和代码现场需要独立建模。
- 现有服务使用 Express/Node、本地 JSON 持久化和静态 Web 预览；尚无 Bun 下 Agent SDK 兼容验证，也未接通 MySQL 或 Android 云真机预览。

工程目录、数据模型、服务契约与迁移边界已写入工程设计。后续实施首先验证 Bun 下 Pi 的真实执行能力，再完成需求与共享工作区适配；本文不代表兼容性测试已经通过。
