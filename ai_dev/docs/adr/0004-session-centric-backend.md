# 串行 Session 接口取代调用方管理的执行协议

2026-09-29，用户确认 Agent 仍在 LLM 后端，同会话轮次严格串行，对外接口要简单。此决策替代 ADR-0003 中 runId、事件重放和崩溃后工具续跑的约定，其他业务/执行边界和后端绑定保持不变。

三个业务接口：POST /chat、POST /stop、GET /sessions/:sessionId。后端生成内部轮次并返回稳定的结果 id；调用方不再生成或传 runId，也不提交 event cursor。结果 id 只区分查询的当前/最近结果。新消息只在 idle 时接受，忙时 409，不排队、不 steering。外部工具 ID 由后端生成并映射模型 ID，会话内唯一。

ai_dev 的业务轮次、候选澄清事务、自动开发去重仍留在 gateway。Agent/原生上下文/内置工具全部在后端。每轮配置不隐式继承。核心 Skill 只需要文本，可选 skillsRoot 仍为同机扩展。

后端持久化累计快照、状态和工具调用；网关发送一次后查询累计结果和 requiredActions。聊天响应或工具回传响应丢失不重发聊天。无法确认发送的窗口如实显示中断，不承诺 exactly-once。可达性丢失期间保持待核实状态，禁止新轮次。停止完成前禁止下一轮。

重启将未完成执行标为 interrupted，保存上下文和现场，不续跑原执行。旧表保留并按会话懒迁移最近结果；本版要求同一会话仅由一个后端进程负责，不支持共享会话的多副本服务。后端自行选择数据库，不能要求替代实现使用本项目表结构。

测试在公开 HTTP/SSE、真实文件及浏览器边界。模型 HTTP 为唯一替代服务；网络故障通过转发真实后端后丢弃响应注入，不伪造业务响应。
