# 协作网关与 Pi 执行服务分离，正常对话增量下发

用户在 2026-09-29 确认采用同一工程内的两个 Bun 服务，首期均运行于本地 Mac，取代单进程建议。协作网关持有需求、会话及 MySQL 数据，不调用模型；执行服务持有活跃 Pi 会话，在代码所在机器完成模型与工具循环。正常请求只下发新消息和必要的需求变化，初始化或实例丢失时才提供初始化信息或持久化的上下文检查点；执行结果与检查点返回网关保存。该边界增加一层本机通信，但让未来网关云端化不必搬迁本机工具循环，首期无需机器调度或消息队列。增量传输不改变模型需要历史上下文的事实，也不保证 Token 节省；恢复对话不等于恢复代码或重放中断工具。
