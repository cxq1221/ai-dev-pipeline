# 需求中心 MVP：模块划分与架构说明

日期：2026-09-28

本文是平台架构综述，说明产品目标、模块分工和核心流程，保留核心输入输出字段供研发参考，不展开完整接口、部署方案与实现细节。以下为设计方案，不代表能力已经实现。

## 1. 产品目标与首期范围

让业务与研发围绕同一个需求，完成从提出需求、AI 辅助开发与实时预览，到自动化测试和产品交付的闭环。

**提出需求 → 澄清与开发 → 运行预览 → 构建与安装 → 自动化测试 → 产品发布**

首期以需求为中心，每个需求对应一个 Android 平台任务。多会话共享代码与预览，各自保留对话上下文，允许并发修改；用户与 AI 均可操作预览，不设置控制权接管。

预览支持小窗、新页面和完整开发桌面入口。支持热更新的应用直接更新；不支持时，通过“重新加载”完成重新构建、安装与启动。设备采用自部署或自研云真机平台，具体产品另行选型。

本期不引入产品版本、冻结、发布渠道、人工验收、独立提交记录页面和用户权限管理模块。

**本期“产品发布”指生成并提供开发者文档、API 文档、示例 Demo、可体验应用和变更日志，不包含生产上线或应用商店上架。**

保留三项核心原则：

- **开发现场持续复用**：一个需求对应一个持久工作区和需求分支。
- **构建与测试对应固定代码**：后续开发不改变历史制品和测试所对应的内容。
- **原始结果与 AI 总结分开**：保留逐用例、逐步骤的测试事实，AI 总结不替代原始结果。

## 3. 模块职责与核心输入输出

字段名为设计参考，不代表已实现 API。各表只列核心业务信息；标注不同操作的字段分别使用，不要求一次调用全部提供。

### 01 需求会话与流程编排

- **职责**：管理需求、资料和会话上下文，组织执行流程，汇总进度与结果。
- **输入**：用户对话、需求资料、操作指令。
- **输出**：执行任务、流程进度，以及需求与代码、预览、制品、报告、发布材料的关联。

| 方向 | 参考字段 | 信息 | 说明 |
|---|---|---|---|
| 输入 | `requirementId / conversationId` | 需求与会话 | 说明本次对话属于哪个需求和会话。 |
| 输入 | `userMessage` | 用户对话 | 原始需求、补充说明或开发指令。 |
| 输入 | `attachmentRefs` | 需求资料 | 截图、设计文件、办公文件和链接。 |
| 输入 | `action` | 操作指令 | 讨论、开发、预览、构建、测试或产品发布。 |
| 输出 | `tasks` | 执行任务 | 需要执行的能力及其业务输入。 |
| 输出 | `progress` | 流程进度 | 当前阶段、执行状态与进度说明。 |
| 输出 | `resultRefs` | 成果关联 | 本需求对应的代码、预览、制品、测试报告和发布材料。 |

- **边界**：管理需求与执行过程，不承担具体编码、构建、安装和测试；需求的理解与澄清由 03 完成。

### 02 开发机管理调度

- **职责**：开发机注册、健康检查、能力匹配与分配，为 AI 开发提供可用的执行环境。
- **输入**：开发机需求，如操作系统、工具链和资源要求；可选指定开发机。
- **输出**：可连接的开发机地址、连接方式与分配结果。

| 方向 | 参考字段 | 信息 | 说明 |
|---|---|---|---|
| 输入 | `workerRequirement` | 开发机需求 | 操作系统、工具链和资源要求。 |
| 输入 | `preferredWorkerId` | 指定开发机 | 可选；指定或复用需求已有的开发机。 |
| 输出 | `workerId` | 开发机标识 | 实际选中的开发机。 |
| 输出 | `developmentConnection` | 开发机连接信息 | 连接地址和连接方式，交给 03 使用。 |
| 输出 | `allocationResult` | 分配结果 | 是否已分配到满足需求的开发机。 |

- **边界**：只管理开发机资源；工作区、仓库和分支直接由 03 中的 Agent 管理。

### 03 AI 代码开发

- **职责**：在指定开发机上运行 Agent，澄清需求、管理工作区和分支、修改代码、执行开发验证，并自主决定提交。
- **输入**：原始需求、用户对话、代码仓库与分支、分支创建策略、开发机连接信息。
- **输出**：澄清后的需求、开发后的代码与固定提交，以及修改说明和开发验证结果。

| 方向 | 参考字段 | 信息 | 说明 |
|---|---|---|---|
| 输入 | `originalRequirement` | 原始需求 | 用户最初提出的业务需求。 |
| 输入 | `userMessage / conversationContext` | 对话与上下文 | 当前指令及所属会话的历史讨论。 |
| 输入 | `repositoryUrl / branch` | 仓库与分支 | 要开发的仓库和需求分支。 |
| 输入 | `branchStrategy / baseRef` | 分支策略与基线 | 复用现有分支或创建新分支，以及创建起点。 |
| 输入 | `developmentConnection` | 开发机连接信息 | 来自 02，指定 Agent 的开发环境。 |
| 输出 | `clarifiedRequirement` | 澄清后的需求 | 整理后的目标、范围和行为要求。 |
| 输出 | `sourceRef` | 开发后的代码 | 仓库、需求分支及本次固定提交或源码快照。 |
| 输出 | `changeSummary` | 修改说明 | 本次完成的功能与主要代码改动。 |
| 输出 | `developmentChecks` | 开发验证结果 | 编译、静态检查、单元测试等结果。 |

- **边界**：负责把需求变成代码；不重复实现设备调度、安装和系统测试能力。

### 04 设备管理调度

- **职责**：发现并注册真机或模拟器，维护连接状态，分配设备，拉起应用，提供应用和完整设备的在线查看与操作。
- **输入**：设备连接地址与类型、设备需求；应用标识及拉起、查看、操作指令。
- **输出**：设备连接信息与状态、应用拉起或操作结果，以及应用和设备的在线查看与操作入口。

| 方向 | 参考字段 | 信息 | 说明 |
|---|---|---|---|
| 输入 | `connectionAddress / deviceType` | 接入：设备地址与类型 | 用于发现和注册真机或模拟器。 |
| 输入 | `deviceRequirement` | 分配：设备需求 | 平台、系统版本、设备能力及开发预览/测试用途。 |
| 输入 | `deviceId / applicationId` | 操作：设备与应用 | 指定要操作的设备，以及需要拉起或查看的应用。 |
| 输入 | `operation` | 操作 | 拉起应用、查看应用、查看完整设备或发送操作。 |
| 输出 | `deviceId / connectionStatus` | 设备标识与连接状态 | 已注册设备及当前是否可连接。 |
| 输出 | `deviceConnection` | 设备连接信息 | 按需求分配的可连接设备地址与连接方式，供 05、06 使用。 |
| 输出 | `launchResult / operationResult` | 拉起或操作结果 | 应用启动和设备交互的执行结果。 |
| 输出 | `appPreviewUrl / devicePreviewUrl` | 在线查看与操作入口 | 应用窗口或完整设备画面的访问与控制入口。 |

- **边界**：应用安装由 05 完成；本模块负责启动与运行交互。开发预览和系统测试使用独立设备占用，避免相互干扰。

### 05 制品构建、管理与部署

**适合各平台独立开发。**

- **职责**：构建 SDK、Demo 等制品，管理下载与来源信息，在指定设备上下载、校验并安装应用。
- **输入**：构建所需的仓库分支或 Tag、构建配置；部署所需的设备连接信息、制品下载地址和安装方式。
- **输出**：制品下载地址与标识、构建日志、各阶段进度、安装结果和已安装应用实例。

| 方向 | 参考字段 | 信息 | 说明 |
|---|---|---|---|
| 输入 | `repositoryUrl / sourceRef` | 构建：代码来源 | 仓库与分支或 Tag，定位本次构建的固定代码。 |
| 输入 | `buildConfig` | 构建：构建配置 | 端类型、SDK/Demo 等目标及所需构建参数。 |
| 输入 | `deviceConnection` | 部署：设备连接信息 | 来自 04，指定安装目标。 |
| 输入 | `artifactId / artifactDownloadUrl` | 部署：制品 | 要安装的制品标识或下载地址。 |
| 输入 | `installMethod` | 部署：安装方式 | 安装通道与覆盖安装、重新安装等方式。 |
| 输出 | `artifacts` | 构建制品 | 制品标识、下载地址、类型及对应代码。 |
| 输出 | `buildLogUrl / stageProgress` | 日志与进度 | 构建日志地址及构建、下载、校验、安装各阶段进度。 |
| 输出 | `installationResult` | 安装结果 | 安装是否完成及实际安装的应用信息。 |
| 输出 | `applicationInstanceRef` | 已安装应用实例 | 关联设备、应用和实际制品，供 04 拉起、06 测试。 |

开发预览与自动化测试共用这套构建和安装能力。

### 06 自动化测试

**适合各平台独立开发。**

- **职责**：将原始用例转成可执行用例，执行测试、采集证据，并生成原始报告与 AI 总结。
- **输入**：原始测试用例；执行所需的可执行用例集、已安装应用实例、设备连接信息和端类型；用于总结的澄清后需求。
- **输出**：转化后的可执行用例、逐用例与逐步骤详情及证据、原始测试报告与结论、AI 总结报告。

| 方向 | 参考字段 | 信息 | 说明 |
|---|---|---|---|
| 输入 | `rawCases` | 转换：原始测试用例 | 用例内容或来源，如 MeterSphere 用例。 |
| 输入 | `targetType / applicationContext` | 转换：端类型与应用信息 | 目标平台和用例执行所需的页面、定位信息。 |
| 输出 | `executableSuite` | 转换：可执行用例集 | 转化后的用例、步骤及脚本。 |
| 输入 | `executableSuite` | 执行：可执行用例集 | 本次要执行的测试内容。 |
| 输入 | `applicationInstanceRef` | 执行：已安装应用实例 | 来自 05，指向本次被测应用及制品。 |
| 输入 | `deviceConnection / targetType` | 执行：设备与端类型 | 设备连接方式和目标平台。 |
| 输入 | `clarifiedRequirement` | 总结：澄清后的需求 | 供 AI 对照测试覆盖情况和业务目标。 |
| 输出 | `caseResults / stepResults` | 用例与步骤详情 | 各用例、各步骤的输入、预期、实际与执行结果。 |
| 输出 | `evidenceRefs` | 测试证据 | 对应步骤的截图、录像和日志。 |
| 输出 | `rawReportUrl / testConclusion` | 原始报告与结论 | 原始测试报告地址，以及通过、失败、跳过等结果。 |
| 输出 | `aiReportUrl` | AI 总结报告 | 基于原始结果和需求生成的总结报告地址。 |

- **边界**：消费 05 的安装结果，需要启动应用时使用 04 的能力；不重复安装，不用 AI 总结覆盖原始测试事实。测试报告与结论交给 07。

05、06 可以由各平台分别实现，对外保持一致的核心输入输出；首期仍只覆盖 Android。

### 07 产品发布

- **职责**：汇集经过测试的开发成果，生成并提供面向开发者与体验者的交付材料。
- **输入**：测完的仓库、分支或 Tag，制品下载地址，澄清后的需求，以及测试报告与结论。
- **输出**：开发者文档、API 文档、示例 Demo、可体验的应用和变更日志。

| 方向 | 参考字段 | 信息 | 说明 |
|---|---|---|---|
| 输入 | `testedSourceRef` | 测完的代码 | 已测试的仓库、分支或 Tag 及对应固定提交。 |
| 输入 | `artifactDownloadUrl` | 制品下载地址 | 与测试记录对应的制品。 |
| 输入 | `clarifiedRequirement` | 澄清后的需求 | 来自 03，用于说明交付目标和功能。 |
| 输入 | `rawReportUrl / aiReportUrl / testConclusion` | 测试报告与结论 | 来自 06，作为发布材料的测试依据。 |
| 输出 | `developerDocUrl` | 开发者文档 | 接入、配置和使用说明的访问地址。 |
| 输出 | `apiDocUrl` | API 文档 | 与本次代码对应的 API 说明地址。 |
| 输出 | `demoUrl` | 示例 Demo | 示例的访问或下载地址。 |
| 输出 | `experienceUrl / applicationDownloadUrl` | 可体验的应用 | 在线体验入口或应用下载地址。 |
| 输出 | `changelog` | 变更日志 | 本次交付的功能与变更说明。 |

- **边界**：不重复实现构建、安装与测试，不包含生产上线。发布材料应对应被测代码和制品，并如实说明测试结果与已知限制。

## 4. 核心流程

### 4.1 开发与预览

1. 用户在需求会话中提出需求、补充资料，01 组织执行。
2. 02 提供开发机，03 在持久工作区中澄清需求、开发和验证。
3. 应用支持热更新则更新预览；否则由 05 构建，并使用 04 提供的设备完成安装。
4. 04 拉起应用，提供在线查看与操作入口，用户通过预览继续反馈。

### 4.2 系统测试与反馈

1. 选择可执行用例集；原始用例由 06 转换。
2. 04 分配测试设备，05 安装固定制品。
3. 06 执行测试，提供逐用例、逐步骤的详情、证据与 AI 总结。
4. 预览反馈或测试发现问题时，回到同一需求继续开发，再构建和测试。

开发过程验证用于辅助编码；系统测试针对固定候选制品。两者不混为一个结果。

### 4.3 产品发布

1. 01 汇集被测代码、制品、澄清后需求和测试结果。
2. 07 生成开发者文档、API 文档与变更日志，提供示例 Demo 和应用体验入口。
3. 发布材料关联回同一需求；后续修改经过新的构建与测试后，再更新交付材料。

**测试结果是发布的输入，不代表测试执行完毕就无条件发布。整个流程允许围绕同一需求反复迭代。**
