# Pi 作为首期执行引擎，平台保有执行与业务边界

2026-09-23 第一轮架构访谈中，用户确认复用现有 Pi 能力作为首期执行引擎，并通过执行 Agent 接口接入。仓库已经具备基于 Pi 的真实模型与工具循环；复用这些能力可以减少重新建设编码循环的工作，同时平台仍需独立表达需求、运行上下文、执行状态及交付结果。

与将现有 Demo 直接扩展成整个业务后台相比，本方案让 Pi 保留在执行侧，平台持有稳定的任务、事件和结果契约。Pi 内部消息、工具实现和 `appID + session` 路由方式不能成为业务对象的唯一标识；更换执行引擎不应要求迁移需求、候选包与测试报告的业务归属。

具体隔离环境、持久化协议、版本升级策略及模型配置将由后续架构设计确定。本决定不表示当前 Demo 已经具备生产任务可靠性或远程执行隔离。
