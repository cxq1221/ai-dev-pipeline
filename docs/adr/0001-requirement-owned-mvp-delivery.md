# MVP 以需求承载开发、候选包和测试记录

当前 MVP 已选择一个需求对应一个 Android 平台任务，并将开发结果、候选包和系统测试记录归属到该需求；这一范围来自用户已确认的产品取舍及当前 MVP 原型，不是本轮新增的技术选型。相比完整原型通过产品版本组织交付，需求中心减少了首期用户在需求与版本之间建立关联的工作，同时使需求成为本期交付记录的核心归属。

需求修订、代码提交、构建批次和测试执行仍需可追溯；它们是不同事实记录，不因为移除产品版本管理而合并为一条可覆盖的“最新状态”。本期不引入人工验收、冻结或发布流程；主干合并边界已由后续 [ADR-0003](0003-requirement-branch-delivery-boundary.md) 确定为外部 Git 流程。

适用基线：`ai-dev-pipeline-mvp-v2.html` 的有效详情定义与测试报告逻辑，以及 `README.md` 的“需求中心 MVP 原型”段落。完整产品说明中的版本组织方式保留为长期产品背景，不决定本期的数据归属。
