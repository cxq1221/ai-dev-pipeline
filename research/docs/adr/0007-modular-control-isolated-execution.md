# 模块化单体控制服务与隔离执行节点

针对内部 20 人在线、5 个开发执行、2 个系统测试并发的设计目标，推荐以模块化单体保存需求与执行状态，PostgreSQL 事务保存业务变更、任务和 outbox；将代码执行、构建、测试和设备媒体通道放在独立执行环境。具体库不是领域边界。

这一方案避免首期引入微服务及多套队列存储的一致性成本，同时保留长任务和源码执行的故障隔离。Agent 统一调度网关是统一协调接口，本身不调用 LLM；执行 Agent 调用模型和受管理工具。首期不以引入 Kubernetes、Kafka 或独立工作流引擎作为前置。

代价是需要认真实现任务租约、幂等、outbox、失效执行隔离与恢复；PostgreSQL 通知不能代替持久任务表，数据库租约过期不能证明外部设备或进程已停止。达到瓶颈后可替换调度实现，业务契约保持稳定。
