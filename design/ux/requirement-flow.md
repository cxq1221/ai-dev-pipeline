# 版本内需求开发 UX 规范

- Status：Implemented prototype；待用户体验反馈。
- Author：Codex，依据用户确认的 UX 评审建议。
- Platform Target：Web，桌面优先，支持移动窄屏；鼠标、触摸和键盘。不要求手柄输入。
- Accessibility Tier：项目尚未指定等级；本规范采用下述基础要求，不宣称已通过 WCAG 合规审计。
- 产品依据：`docs/prototype-scope.md`、`docs/adr/0001-version-organized-delivery.md`。不涉及游戏 HUD 或 GDD。

## 用户需要与进入上下文

业务用户进入一个已选定版本，想提出一项具体改变、确认目标并体验结果。用户不需要知道构建脚本或如何运行测试。研发人员进入已通过业务验收的单条需求进行审查；发布人员进入已完成回归的版本进行发布批准。

## 导航与入口出口

侧栏：工作台、版本中心、全部需求。版本内部：本版需求、版本测试与发布。

需求入口来自本版列表、跨版本全部需求、工作台待办或稳定 URL `#r/{version}/{request}`。需求详情面包屑返回所属版本；不能通过切换版本暗中改变正在查看的需求。版本内列表只显示本版；全部需求独立标明各项所属版本。

## 布局与组件

| 区域 | 信息 | 操作 |
|---|---|---|
| 顶部定位 | 所属版本、需求标题、编号和状态 | 返回版本 |
| 下一步 | 当前进展、负责角色、需要用户做什么 | 当前唯一主操作，必要时有修改意见次操作 |
| 我要改什么 | 原始描述、目标、验收标准 | 草稿阶段确认标准和示例文案 |
| 修改结果 | 空态、进行中、需求预览 | 操作预览 |
| 过程与证据 | 开发事件、自测、失败、修订与反馈 | 默认折叠，逐项展开 |

版本号只用于确定工作上下文；RC 与制品信息主要出现在版本测试与发布页。

## 状态与行为

| 状态 | 页面反馈 | 下一步 |
|---|---|---|
| 草稿 | 待确认，显示目标与验收标准 | 业务用户确认并启动 |
| AI 开发 / 自测 | 自动进行，不展示手动构建或运行自测按钮 | 无需操作，可离开页面 |
| 自测失败 | 明确 AI 正在修复，失败记录保留 | 原型自动修复并重测 |
| 等待验收 | 显示预览与当前需求目标 | 业务用户通过或提出修改意见 |
| 等待研发审查 | 明确等待研发负责人 | 研发通过或退回 |
| 可纳入交付 | 本需求已就绪，不代表版本发布完成 | 返回版本交付 |

新版本空列表显示新增引导；搜索无结果显示无匹配。无效路由显示找不到记录与返回入口。未填必填字段由表单提示；验收标准为空时阻止启动并显示原因。没有真实异步接口，因此 API 网络加载与认证错误不属于本阶段实现；AI 过程使用进行中状态演示。

自动进度每 1.4 秒推进一次，正常演示约两个推进周期，失败修复约四个；完成后不自动业务验收。预览重试约 1.1 秒。操作提示显示 4 秒，但关键失败原因和当前状态另保留在页面或证据中。

## 数据职责和更新

- `model.mjs` 持有版本、独立需求、修订、运行记录、候选范围快照及发布记录；视图只根据模型呈现。
- `localStorage` 保存演示工作区。迁移前备份旧格式，保留历史制品、测试和发布记录。
- 用户动作通过模型操作更新；定时器推进所有正在运行的需求。切换页面不会停止执行。
- 正在填写表单或展开证据时，延后页面重绘，避免打断输入；关闭后更新。
- 无日期显示“未安排”；没有候选显示“尚无当前候选”；没有自测显示“尚未自测”；列表为空提供明确下一步。

## 操作与记录

新增版本、新增需求、确认开发、自动执行步骤、自测失败/成功、业务验收、研发审查、返修、版本构建与回归、发布、同步均记录或更新相应模型事实。导航、展开证据、搜索和角色演示切换不产生业务执行事件。

## 输入与焦点

页面 Tab 顺序为侧栏 → 演示角色 → 面包屑与页面操作 → 目标及表单 → 预览 → 过程证据。按钮可用 Enter/Space 激活，链接和表单使用原生键盘行为。

弹窗打开后聚焦第一个输入框，没有输入框则聚焦关闭按钮；背景设为 inert，Tab 在弹窗内循环，Escape 关闭，关闭后回到触发按钮或页面标题。路由变化聚焦新标题，后台进度不强制抢焦点。

## 无障碍与动画

状态包含文字，不只依靠颜色。提供可见焦点、表单 label、dialog 标签、live 状态提示；自动进度只在状态变化时播报。动态装饰使用减弱运动偏好降级。正文建议满足 4.5:1、控件和焦点 3:1；本轮未完成所有色值的正式对比度审计，不标记合规通过。

导航直接切换，不以入场动画阻碍操作；关闭弹窗直接恢复焦点。进行中圆点使用 1.4 秒装饰动画，非理解状态的必要条件。

## 文案与本地化

需求标题与版本目标最多 100 字，描述 3000 字，验收标准与反馈 2000 字，预览文案 120 字。正文保留换行并可折行，窄屏列布局折为单列；本轮只提供中文，未来本地化预留约 40% 文案膨胀空间。

## 可执行验收条件

1. 在一个版本新增两条需求，编号不同；编辑或返修第一条不会改变第二条。
2. 在本版列表不能看到其他版本需求；全部需求页明确显示各项所属版本。
3. 确认一次开发后，无需点击构建和自测，页面自动到达等待验收；正常演示前台约 3 秒内完成。
4. 失败演示保留失败和成功两次自测记录，并自动完成修复；业务验收仍需人工点击。
5. 任何一条需求未完成验收和研发审查时，版本候选构建不可用并解释原因。
6. 所有需求就绪后，一次操作自动构建版本并回归；只有发布负责人可批准已通过的当前候选。
7. 候选通过后新增需求或返修，旧候选证据保留，但不能用于新范围发布。
8. 弹窗可完全用键盘填写、提交和关闭；关闭后焦点回到调用位置。
9. 在 390px 宽度与常见桌面视口检查页面无整体横向溢出；候选表允许局部横向滚动。
10. 页面切换使用本地数据应在 300ms 内响应；这是目标，不代表本轮完成性能基准测试。

## 模式库状态

项目没有独立交互模式库。此规范记录本轮统一采用的版本导航、下一步提示、折叠证据、带焦点管理的表单弹窗模式，后续可提取复用。
